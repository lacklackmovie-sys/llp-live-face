# LLP LIVE FACE

사진 한 장(JPG/PNG/WEBP)을 올리고 마이크로 말하면, 사진 속 인물의 입이 **음량에 따라** 실시간으로 움직이는 웹앱입니다. GPU 서버 없이 브라우저에서만 동작합니다.

- 주소: https://llp-live-face.pages.dev (Cloudflare Pages 프로젝트 `llp-live-face`)
- 기본 캐릭터: 첫 실행 때 스튜디오 사진(`public/demo.jpg`)이 라이브러리에 자동 등록됩니다. 삭제하면 다시 생기지 않습니다.

## 처음 쓰는 법 (3단계)
1. **📷 사진 선택**: 기본 캐릭터가 이미 들어 있어서 바로 써도 됩니다.
2. **🎙 마이크 켜기**: 권한 허용을 누르세요.
3. **📺 방송 시작**: 캐릭터만 전체화면으로 나옵니다.
- 화면 위 **❓ 사용법**을 누르면 언제든 설명을 다시 볼 수 있습니다.
- 슬라이더는 **세부 설정** 탭에 모여 있고, 기본값만으로도 쓸 수 있습니다.
- 캐릭터와 설정은 자동으로 저장되고, 새로고침해도 그대로 돌아옵니다.

## 할 수 있는 것
- 사진 업로드 → MediaPipe Face Landmarker(IMAGE 모드)로 얼굴 검출. 얼굴이 없으면 안내하고, 여러 명이면 탭해서 고릅니다. EXIF 회전을 반영하고 긴 변을 1600px로 줄입니다.
- WebGL 2D 메시 변형: 입술·턱 주변만 움직이고, 입 안은 원래 입술선 색을 어둡게 그라데이션으로 칠합니다(검정 타원을 덮지 않음). 머리 움직임은 얼굴·머리 영역 가중치로만 적용해 배경과 옷은 고정됩니다.
- 마이크: 버튼을 누를 때만 켜집니다. AudioWorklet으로 RMS를 계산하고 노이즈 게이트·감도·스무딩을 거칩니다. 정지하면 트랙과 AudioContext를 해제합니다. **음성은 어디에도 업로드하지 않습니다.**
- 실시간 립싱크 지연을 줄였습니다. 소리를 약 11ms마다 분석하고 입이 열리는 반응은 약 10~35ms로 맞췄습니다(스무딩 설정에 따라 다름). 실제 체감 지연은 기기와 마이크에 따라 달라지며 실측하지 않았습니다.
- **상체 움직임**: 약 4초 주기로 호흡하듯 가슴이 오르내리고, 말할 때 어깨와 상체가 살짝 흔들립니다. 세부 설정에서 끄거나 크기를 조절할 수 있습니다.
  - 사진을 2D로 늘이고 기울이는 효과라서 **팔이나 손이 따로 움직이지는 않습니다.**
  - 사진 가장자리는 고정되지만, 몸 바로 옆 배경은 아주 조금 같이 움직일 수 있습니다.
- **내 모션 클립**(선택): 같은 캐릭터로 만든 짧은 MP4/WebM 영상을 넣으면 버튼(단축키 A, S, D, F…)을 눌렀을 때 재생됩니다. AI로 만든 손인사나 춤 영상 같은 것들입니다.
  - 재생이 끝나면 0.3초 크로스페이드로 실시간 사진에 돌아옵니다. 클립은 이 기기 IndexedDB에 저장됩니다.
  - 클립 재생 중에는 입이 목소리를 따라가지 않고, 클립 소리는 꺼집니다.
  - **앱 안 녹화 파일에는 클립이 들어가지 않습니다.** OBS 창 캡처에는 보입니다.
  - 앱이 직접 손이나 춤 영상을 만들어 주지는 않습니다.
- **방송 중 끊김 방지**:
  - 한 프레임에서 오류가 나도 마지막 화면이 그대로 유지됩니다.
  - GPU(WebGL) 컨텍스트가 사라지면 그동안 원본 사진을 띄우고 자동으로 복구합니다.
  - 오디오가 멈추면(탭 전환, 절전 등) 자동으로 다시 켭니다.
  - 마이크 장치가 끊기면 자동으로 재연결을 시도합니다.
  - 지원하는 브라우저에서는 화면 꺼짐 방지(Wake Lock)를 사용합니다.
  - 예기치 못한 오류가 나면 앱이 스스로 다시 뜨고, 캐릭터와 설정을 복원합니다.
- 조절 슬라이더: 감도, 게이트, 입술 변형 강도, 변형 범위, 스무딩. 자동 깜빡임과 미세 고개 움직임은 켜고 끌 수 있습니다.
- 리액션(키 1~7): 끄덕, 도리도리, 갸우뚱, 웃음 들썩, 깜짝 줌, 윙크, 깜빡
- 댄스(Q, W, E, R / 정지 0): 스웨이, 바운스, 그루브, 펌핑 줌. BPM 슬라이더와 탭 템포로 박자를 맞춥니다. **사진 전체를 움직이는 2D 모션이며 전신 춤이 아닙니다.** 음악 박자 자동 인식은 없습니다.
- 화면비는 16:9, 9:16, 1:1을 고를 수 있습니다. 사진은 꽉 채우기와 전체 보기 중에 고릅니다. 배경색은 블랙, 그린·블루 크로마, 화이트, 직접 선택이 있습니다.
- 녹화: 캔버스 영상과 마이크 소리를 한 스트림으로 MediaRecorder에 녹화합니다.
  - 브라우저가 지원하는 MP4/WebM 형식만 표시합니다.
  - 해상도는 720p와 1080p입니다. 4K는 기기별 검증 전이라 꺼 두었습니다.
  - 미리보기를 보여 주고, 저장은 iOS면 공유 시트로, 그 외 기기는 다운로드로 처리합니다. 실패하면 원인을 표시합니다.
- 캐릭터 라이브러리는 IndexedDB(이 기기 브라우저)에 저장되고 추가, 삭제, 교체할 수 있습니다.
- 상단에 렌더러, 얼굴인식, 마이크, FPS와 프레임 처리 시간을 표시합니다.
- PWA: 홈 화면에 추가할 수 있고 service worker가 자산을 캐시합니다.
- AI 탭: GPU 서버 `/health` 확인만 합니다. 준비된 서버와 스트리밍 클라이언트가 없으므로 **AI 모드 버튼은 비활성**입니다. 자세한 내용은 `server/README.md`에 있습니다.

## 한계 (솔직하게)
- 발음(음소)에 맞춘 립싱크가 아니라 **소리 크기에 따라 입이 열리고 닫히는 방식**입니다.
- 사진 한 장으로는 치아나 혀를 만들어낼 수 없어서 입 안은 어둡게 보입니다.
- 크게 벌리면 턱선이 약간 휘어 보일 수 있습니다. 그럴 땐 '입술 변형 강도'와 '변형 범위'를 낮추세요.
- 옆얼굴, 손이나 마이크가 입을 가린 사진, 아주 작은 얼굴은 결과가 어색하거나 검출에 실패합니다.

## 방송(아프리카TV/SOOP, 유튜브 라이브 등)에서 쓰기
1. PC 크롬이나 엣지에서 사이트를 열고, 캐릭터를 고른 뒤 **마이크 시작**을 누릅니다.
2. **방송 모드**(B 키)를 누르면 UI가 사라지고 캐릭터만 전체화면으로 나옵니다. Esc로 나갑니다.
3. OBS/PRISM에서 **윈도우 캡처**로 이 브라우저 창을 잡습니다. 배경을 그린(크로마)으로 하면 OBS의 '크로마 키' 필터로 사진 바깥 영역을 뺄 수 있습니다. 사진 속 배경은 그대로 남습니다.
4. 방송 중 리액션은 키보드 1~7, 댄스는 Q/W/E/R, 정지는 0입니다. 태블릿에서는 화면을 탭하면 버튼 메뉴가 나오고, 다시 탭하면 숨겨집니다.
5. 실제 방송 음성은 지금처럼 OBS 마이크로 보내면 됩니다. 이 앱은 입 모양만 만듭니다.
- 태블릿·폰만으로 방송한다면 PRISM이나 SOOP 앱의 '화면 공유'로 이 화면을 송출하세요. 이 방법은 기기 검증을 하지 않았습니다.
- OBS '브라우저 소스'는 마이크 권한 처리가 복잡해서 윈도우 캡처를 권장합니다.

## 실행 / 빌드 / 테스트
```bash
npm install
npm run dev          # 개발 서버
npm run build        # tsc + vite build → dist/
npm test             # vitest 단위 테스트 (오디오 RMS/게이트/스무딩, 메시, MIME, EXIF, 모션, AI 상태)
npx playwright install chromium && npm run test:e2e   # 헤드리스 크롬 스모크 테스트 (가짜 마이크)
npm run deploy       # Cloudflare Pages 배포 (wrangler 로그인 필요)
```
Vercel로 배포하려면 `vercel.json`을 사용합니다. 저장소를 import하기만 하면 됩니다.

## 검증 현황
**자동 테스트 완료 (리눅스 헤드리스 Chromium, 가짜 장치)**
- 단위 테스트 25개 통과
- E2E 모션 클립/상체 7개 통과 (`tests/e2e/clips.mjs`)
  - 상체 픽셀 변화
  - 클립 저장, 재생, 페이드인, 복귀
  - 새로고침 후 유지
  - 단축키
- **장시간(soak) 테스트 11분** (`tests/e2e/soak.mjs`, 상체/클립 기능 추가 전 빌드)
  - 방송 모드와 가짜 마이크로 10초마다 화면을 검사했습니다. 65회 검사 중 빈 화면은 0회였습니다.
  - JS 힙은 처음 10.6MB에서 마지막 10.9MB로 늘지 않았습니다. 페이지 오류는 0건입니다.
  - 테스트 도중 일부러 일으킨 장애와 결과:
    - 2분: WebGL 컨텍스트 손실 → 정지 사진을 표시하고 복구
    - 4분: AudioContext suspend → 4초 안에 running
    - 6분: 마이크 트랙 종료 → 자동 재연결
    - 8분: visibilitychange 이벤트
  - 같은 테스트를 최종 빌드에서 3분 동안 다시 돌렸습니다(아래 보고 참고).
- E2E 13개 통과
  - WebGL2 초기화
  - 기본 캐릭터 얼굴 검출과 저장
  - 입 변형 렌더 (스크린샷으로 확인)
  - AudioWorklet 마이크 입력에 따른 입 열림
  - 녹화(MP4)와 미리보기
  - 마이크 정지 시 자원 해제
  - 방송 모드 UI 숨김
  - 얼굴 없는 사진 오류 안내
  - 마이크 권한 거부 안내
  - manifest와 service worker 제공
  - JS 오류 없음

## 🎞 메인 영상 (기본 동작 반복 영상)
- 메인 화면의 **'🎞 메인 영상 바꾸기'** → '＋ 새 영상 올리기'로 MP4/WebM/MOV 선택. 얼굴을 0.1초 간격으로 자동 추적한 뒤 즉시 교체 (새로고침 없음).
- 여러 개 저장(이 기기 IndexedDB), 언제든 골라 쓰기 · ✕ 삭제 · **'📷 사진으로 되돌리기'**.
- 영상 위에 마이크 음량 입 움직임이 얼굴을 따라가며 입혀짐. 리액션·댄스·클립 후 영상으로 복귀.
- 끝↔처음은 크로스페이드로 이어짐 (기본 영상은 앞으로+뒤로 핑퐁으로 미리 만들어 끊김 없음).
- 교체 중에는 새 영상이 준비될 때까지 이전 화면 유지 (방송 중에도 빈 화면 없음). 재생 실패 시 사진으로 자동 전환.


## 🎬 모션 클립 재생
클립마다 **1회 / 🔁 반복** 재생을 고를 수 있습니다(기본 1회). 같은 클립을 다시 누르거나 **클립 정지**, 다른 리액션·댄스를 누르면 멈춥니다.

## 🔌 OBS 연결 (웹소켓)
브라우저에서 OBS를 직접 실행할 수는 없습니다. **OBS 28+ 내장 웹소켓**으로 연결합니다.

1. OBS를 켠 뒤 **도구 → 웹소켓 서버 설정**에서 사용을 켭니다 (기본 `ws://127.0.0.1:4455`, 비밀번호 선택).
2. 앱의 **🔌 OBS 연결** 버튼을 눌러 호스트·비밀번호를 입력하고 **연결**합니다.
3. 연결되면 현재 씬에 브라우저 소스 **「LLP LIVE FACE」**(1920×1080, `?broadcast=1`)가 생기거나 갱신됩니다.
4. (선택) **방송 시작/중지**는 OBS에 이미 설정해 둔 스트림으로 송출합니다. 스트림 키는 OBS 설정을 따릅니다.

호스트·비밀번호는 이 기기 `localStorage`에만 저장됩니다. 같은 PC의 OBS만 지원이 가장 안정적입니다(HTTPS 페이지 → `ws://127.0.0.1`).
